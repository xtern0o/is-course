# Локальный запуск trace

Команды ниже выполняются в PowerShell из корня проекта. Нужны Docker Desktop и JDK 21. React собирается в контейнере Node 22. Порты 8080, 8180 и 55432 должны быть свободны.

Для запуска из корня выполните `powershell -ExecutionPolicy Bypass -File .\Start-Trace.ps1`. Скрипт выполняет описанные ниже команды, ждёт Keycloak и запускает Spring.

### Обновление предыдущей сборки

Остановите прежний bootRun через Ctrl+C. Распакуйте файлы поверх предыдущих исходников в ту же папку trace-core, чтобы Compose использовал прежний том PostgreSQL. Локальные вложения находятся в backend/data. Если вручную добавляли пользователей или меняли пароли через консоль старого Keycloak, перед пересозданием контейнера сохраните его базу: в предыдущей сборке она жила внутри контейнера. Для стандартных student и teacher новая конфигурация содержит те же идентификаторы.

```powershell
docker compose up -d
docker run --rm --mount "type=bind,source=$($PWD.Path),target=/project" --mount "type=volume,target=/project/frontend/node_modules" -w /project/frontend node:22-bookworm sh -c "npm ci && npm run build"
cd .\backend
.\gradlew.bat --console=plain bootRun
```

Если Keycloak ещё загружается, дождитесь ответа от http://localhost:8180/realms/trace/.well-known/openid-configuration и повторите bootRun. Новая конфигурация сохраняет базу Keycloak в именованном томе trace-keycloak. Для повторных запусков без изменений frontend достаточно docker compose up -d и bootRun.

Открыть http://localhost:8080 в браузере. Используйте именно localhost, поскольку это адрес возврата после SSO. Spring раздаёт собранный React и REST API с одного порта. После изменений frontend повторите сборку frontend и перезапустите backend. При первом старте Flyway создаёт таблицы в выделенной БД trace. Характеристики схемы соответствуют sql/01_schema.sql и sql/02_indexes.sql из ветки dev; вручную исполнять эти скрипты для локального запуска не требуется.

| Логин | Пароль для локальной проверки | Тип создаваемого проекта |
|---|---|---|
| student | student-local | Организация |
| teacher | teacher-local | Учебный проект |
| admin | admin-local | Управление пользователями TRACE |

## Регистрация и права

Откройте TRACE в приватном окне и выберите регистрацию на странице входа. После заполнения профиля пользователь получает роль студента. Чтобы дать ему роль преподавателя, войдите под admin в другом окне, откройте «Пользователи», найдите аккаунт по имени, почте или логину, нажмите «Изменить» и сохраните роль. В первом окне обновите страницу. Права на API действуют со следующего запроса.

В том же разделе можно создать аккаунт с временным паролем. При первом входе Keycloak предложит задать постоянный. Раздел показывает зарегистрированные в TRACE профили и созданные через панель аккаунты. Импортированные в Keycloak демонстрационные профили появляются после первого входа. Приостановка блокирует API TRACE, в том числе для открытой сессии. Восстановление доступа выполняется тем же переключателем. Собственные права администратора защищены от случайного изменения.

## Проверка в браузере

1. Войдите как student, создайте организацию, укажите название, цель и описание.
2. Измените цель и вернитесь в каталог. Откройте карточку повторно.
3. Выйдите и войдите как teacher. Откройте организацию студента. Изменение доступно её управляющему. Затем создайте учебный проект и проверьте, что каталог содержит обе записи.
4. Для проверки сохранения данных остановите backend через Ctrl+C, запустите снова и откройте каталог.

## Автоматические проверки

Из backend выполните `.\gradlew.bat clean test` при работающем Docker Desktop. Testcontainers создаёт отдельную PostgreSQL, Flyway применяет миграции, MockMvc вызывает HTTP-контроллеры с тестовым OIDC-пользователем. Операции проверяют реальные транзакции и объектные права. Отчёт находится в build/reports/tests/test/index.html. Для окружения с выделенной тестовой PostgreSQL предусмотрен TRACE_TEST_DB_URL; указывайте только отдельную тестовую БД, пользователь trace и пароль trace-local. Тест записывает данные.

## Использование в следующих модулях

- GET /api/me возвращает локальный UUID пользователя, имя, роль и CSRF-токен. Для POST и PATCH нужно передать токен в заголовке, имя которого приходит в csrfHeader.
- GET /api/projects?page=0&size=20 возвращает items, page, totalPages. Каталог доступен вошедшим пользователям. Размер страницы 1–100.
- POST /api/projects принимает name, type, goal, description. Типы educational и development проверяются по роли. Управляющий определяется сервером.
- GET /api/projects/{id} возвращает карточку. PATCH принимает изменяемые поля name, goal, description. Получить карточку другого проекта можно, редактирование доступно управляющему.
- Карточка проекта объединяет команды, заявки, шаблоны, задания и назначения. Базовый путь этих коллекций — /api/projects/{id}. Для распределения уже созданного задания используется POST /api/projects/{id}/tasks/{task}/assignments.
- Карточка назначения и его история доступны по GET /api/assignments/{id}. Относительно этого пути POST /attempts принимает multipart с полями content и files. POST /attempts/{attempt}/review принимает решение accepted либо revision_required. Для возврата нужен комментарий. GET /discussion возвращает сообщения команды и объявления для всех команд задания.
- Дальнейшие изменения схемы оформляются следующей версией Flyway в backend/src/main/resources/db/migration. Опубликованные миграции сохраняют исходные контрольные суммы.

Остановить backend через Ctrl+C, затем выполнить `docker compose down` из корня. Именованный том PostgreSQL сохраняет проекты между запусками. Конфигурация Keycloak и пароли предназначены для локальной разработки.

## Сквозная проверка для двух участников

Откройте приложение в двух отдельных профилях браузера или в обычном и приватном окнах. В одном войдите как teacher, в другом как student. При первом входе локальная запись пользователя создаётся из данных Keycloak.

1. Преподаватель создаёт учебный проект и в карточке создаёт команду. Набор изначально открыт.
2. Студент открывает проект в каталоге и отправляет заявку. Преподаватель обновляет карточку и принимает заявку. В учебном проекте можно также распределить уже входившего студента напрямую.
3. Преподаватель раскрывает «Новый шаблон задания», задаёт ожидаемый результат и добавляет обязательный целочисленный параметр «Вариант». В разделе «Задание и назначение» создаёт задание, выбирает команду и задаёт ей вариант. При необходимости можно сохранить задание и распределить его позже.
4. Студент обновляет карточку, открывает назначение, проверяет свой вариант и отправляет текст с файлом. Преподаватель открывает очередь «Только ожидающие проверки», скачивает вложение и возвращает работу с замечанием.
5. Студент нажимает «Обновить историю», отправляет исправление, преподаватель принимает вторую попытку. В истории остаются обе версии и решения. Объявление к заданию видно всем назначенным командам, сообщения и вложения каждой команды доступны внутри её назначения.

## Как разделены исходники

TRACE запускается как один Spring Boot-процесс. Пакеты Kotlin отражают области ответственности: identity связывает сессию с локальным пользователем, projects ведёт каталог и права управляющего, teams отвечает за набор, assignments — за распределение и выполнение, communication — за обсуждения. Контроллеры принимают HTTP-запросы, сервисы проверяют права и координируют операции. Проекты используют Spring Data JPA и Hibernate. Для командных операций сервисы используют Spring JDBC и функции PostgreSQL из модели второго этапа. Составная операция, например сдача с вложением, выполняется в одной транзакции.

React-экраны расположены в frontend/src. Workspace связывает команды и задания с карточкой проекта. Teams отвечает за состав и набор, Allocation — за конструирование заданий, Assignment — за сдачу и проверку. В ui.jsx находятся общее поле, формы с обработкой ошибок и повторных нажатий, раскрываемые панели и клиент REST с CSRF. Состояние после действий в другом окне обновляется кнопкой на экране или повторным открытием карточки.

В PostgreSQL хранятся метаданные попытки и ключ объекта. Локальная реализация AttachmentStore хранит байты по ключу в backend/data/attachments при запуске из backend. Каталог настраивается через TRACE_ATTACHMENTS_DIRECTORY и должен сохраняться вместе с базой при резервном копировании. Доступ на скачивание проверяет backend. Ограничения локальной сборки: 10 МиБ на файл, 20 МиБ на весь multipart-запрос. Для приёмки по NFR ещё требуются отдельные нагрузочные и пользовательские испытания из спецификации.

## Профиль и формы

Нажмите «Мой профиль» под своим именем в боковой панели. Можно изменить имя в TRACE, указать специализацию и написать о себе. Предпросмотр показывает, как будет выглядеть карточка в составе команды. Публикация специализации и биографии в списках участников включается отдельно. Такие списки доступны вошедшим пользователям проекта через каталог. Имя используется также в проектах и обсуждениях. Данные входа и настройки пароля доступны по ссылке в разделе «Учётная запись».

Состав команды и заявки открываются на месте. Формы создания команды, назначения, заявки, сдачи работы и комментария открываются в диалоговом окне с контекстом выбранного объекта. Escape или кнопка закрытия возвращают на страницу. Пока пользователь остаётся на том же экране, закрытую форму можно вновь открыть с введённым текстом. После успешной отправки форма закрывается и появляется подтверждение.
