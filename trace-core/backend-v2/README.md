# trace-core backend

## Отхождения от спецификаций

Здесь мы бы хотели указать, в каких местах получились рахождения с первыми двумя документами в рамках бекенда (взаимодействие с бд)

- повторная сдача разрешена даже после `completed`.
- `team_member` и `team_task_parameter_value` используют отдельный `uuid` вместо составного первичного ключа - так проще на бекенде
- ссылки сообщения на сдачу и проверку используют `on delete cascade` вместо `set null`.
- идентификаторы `uuidv7` генерируются hibernate, а не через `default uuidv7()` в postgresql.
- процедуры `apply_to_team`, `review_team_application`, `submit_task` и `review_submission` перенесены в сервисный слой и не создаются в бд, мне показалось это повторение бизнес логики
